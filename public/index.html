03 / TROUBLESHOOTING

Resolver un error de OAuth

El redirect URI debe coincidir exactamente entre la configuración del servidor y Discord Developer Portal. El callback definido en esta aplicación es /api/auth/discord/callback.

Si hay un error de permisos, revisá que el bot tenga Manage Roles y que su rol más alto esté encima de zerqonviphub.

HELP CENTER / 07

Preguntas frecuentes.

Respuestas directas para conectar tu cuenta y resolver problemas.

¿Por qué Discord no me asigna VIP?+

La cuenta debe pertenecer al servidor y el bot debe tener permiso Manage Roles, estar por encima del rol VIP y usar los IDs correctos. Abrí System Status para ver los diagnósticos disponibles.

¿Por qué dice que el redirect URI no es válido?+

La URI completa en Discord Developer Portal debe coincidir exactamente con la usada por el backend. En esta aplicación la ruta es /api/auth/discord/callback; el dominio real depende del despliegue.

¿Qué pasa si cierro sesión?+

El portal intenta remover el rol VIP y confirmar la operación antes de revocar la sesión. Si Discord falla, se cierra la sesión de todas formas y el backend registra un reintento pendiente.

¿Cerrar Discord quita el VIP?+

No. Cerrar la aplicación Discord no equivale a salir del servidor. Si abandonás el servidor, Discord quita sus roles automáticamente y el bot puede invalidar la sesión de la web cuando recibe el evento correspondiente.

¿La web ejecuta el loadstring?+

No. La web solo muestra y copia el loader, y puede consultar si la fuente responde. No ejecuta Luau en el navegador.

¿Qué hago si compartí un token por error?+

Revocá o regenerá inmediatamente el token afectado desde Discord Developer Portal y actualizá el secreto en el entorno del servidor. No lo vuelvas a pegar en el código ni en el chat.

TRUST CENTER / 08

Privacidad por diseño.

Una explicación legible de los datos usados por la implementación de este portal.

Información esencial

Este documento es una plantilla técnica del proyecto y debe revisarse antes de su publicación formal.

Última actualización: 15/10/2026

Información procesada

La aplicación solicita autorización de Discord para identificar la cuenta. Para gestionar la verificación puede guardar el ID de Discord, nombre visible, avatar, estado del rol, marcas de tiempo de verificación y datos técnicos de sesión.

Uso de los datos

Estos datos se utilizan para completar OAuth2, consultar membresía y rol VIP, mostrar el estado de la cuenta, proteger la sesión y diagnosticar errores de asignación. El backend almacena los registros de sesión y estado en una base SQLite local del servicio.

Secretos y seguridad

El token del bot, el secreto OAuth y el secreto de sesión no deben enviarse al navegador. La aplicación no necesita mostrar esos valores para funcionar. Los registros de auditoría evitan guardar códigos OAuth o tokens de acceso.

Retención y eliminación

Las sesiones expiran según su cookie y la base guarda registros de estado y auditoría. Esta versión no incorpora un panel autoservicio para borrar por completo todos los registros; cualquier política legal de retención debe configurarse y comunicarse explícitamente antes de producción.

Servicios externos

Discord se utiliza para autenticación y gestión de roles. GitHub Raw se utiliza como fuente del loader y puede comprobarse desde el backend. Google Fonts se utiliza para tipografía si el navegador permite acceder a ese servicio.

Contacto

La dirección de soporte oficial debe configurarse por el propietario antes de publicar una política definitiva.

PORTAL GUIDELINES / 09

Términos de uso.

Condiciones iniciales para utilizar el portal. Revisá esta plantilla antes de convertirla en un documento legal definitivo.

Uso del portal

El portal ofrece una interfaz para consultar información del hub, copiar un loader y realizar una verificación de Discord. El usuario es responsable de seguir las reglas de las plataformas y los servicios que utiliza.

Autenticación y roles

La asignación y eliminación de roles depende de la configuración del bot, de los permisos del servidor y de la respuesta real de Discord. El sitio no debe presentar una operación como exitosa si no fue confirmada.

Disponibilidad

Los servicios de Discord, el hosting y GitHub pueden experimentar interrupciones. El portal muestra el estado disponible en el momento de la comprobación, pero no garantiza disponibilidad permanente.

Actualizaciones

Los cambios de la web y del script deben reflejarse en el changelog cuando hayan sido confirmados. Las fechas, versiones y funciones no deben inventarse.

Contacto y revisión

Configurá un canal de soporte oficial y revisá estos términos para adaptarlos a tus necesidades antes de publicarlos como términos definitivos.
